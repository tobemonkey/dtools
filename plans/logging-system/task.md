# 日志系统规范与请求详情日志任务

## 背景

当前项目已经具备 TraceID、统一异常处理和登录审计雏形，但正常请求链路、请求参数诊断、日志文件分层和日志保留策略仍不完整。

本任务目标是在不影响业务主流程的前提下，建立第一版日志系统规范和请求详情日志能力。

## 目标

- TraceID 进入日志上下文，便于通过单个 traceId 串联请求链路。
- 新增独立请求详情日志文件，用于记录请求参数诊断信息。
- 请求详情日志支持配置开关，可通过 `application.yml` 或 JVM 启动参数覆盖。
- 请求详情日志采用异步处理，队列满、脱敏失败或写入失败均不得影响业务请求。
- 请求参数脱敏只通过注解声明，不做字段名兜底脱敏。
- 日志文件支持按天滚动、超过指定天数自动清理，并限制总大小。

## 非目标

- 第一阶段不记录响应体。
- 第一阶段不引入审计通用表，只保留现有登录审计表。
- 第一阶段不对历史 DTO 强制补齐所有敏感注解，只对本次涉及的高风险字段补充。
- 第一阶段不实现按 traceId 动态开启日志、按 URI 白名单开启日志等高级诊断模式。

## 验收命令

- 后端编译：`mvn -q -DskipTests compile`
- 后端测试：`mvn -q test`
